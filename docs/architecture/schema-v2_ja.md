# スキーマ v2 の設定スコープ

[English](schema-v2.md)

## 設定ファイルの契約

スキーマ v2 では、設定ファイルのスコープを二つ定義します。リポジトリ用は
`scope: repository` で一つのリポジトリを指定し、v1 と同じ設定項目とパスを使います。
個人用は `scope: personal`、GitHub ログイン名を表す `account`、任意の `issueTypes` と
`issueFields` の一覧を持ちます。両方のスコープの項目を同じファイルに書くとエラーになります。
YAML と JSON を受け付け、未知のキーと重複したマッピングキーを拒否します。
既存の JSON Schema は v1 と v2 を検証します。`validate` は両方のスコープに対応します。

GitHub は個人アカウントの Issue 定義を、そのアカウントが所有する全リポジトリで利用できるようにします。
拡張機能では `personal` サブコマンドで管理し、個人設定を読み書きする前に認証中のログイン名と
設定ファイルのアカウントを照合します。リポジトリ用コマンドはリポジトリ設定とその API を使います。
リポジトリの import は既定で v1 を出力し、新規出力時に v2 を選べます。既存ファイルの更新では
更新先のバージョンを維持します。

## 個人アカウントの定義

Issue type は `name` と `isEnabled` を必須とし、`description` と `color` を指定できます。
Issue field は `name` と `dataType` を必須とし、`description`、`visibility`（`restricted` または
`all`）、選択型の場合は `options` を指定できます。型は `text`、`number`、`date`、
`single_select`、`multi_select` です。選択肢は `name`、`color`、整数の `priority` を必須とし、
`description` を指定できます。同じ一覧内で大文字と小文字だけが異なる名前は重複として扱います。
一つのアカウントで型とフィールドをそれぞれ最大 25 個宣言できます。選択型を新規作成する際は
選択肢が必要です。フィールドのピン留めとピン留めしたフィールドの順序は GitHub の設定画面で管理します。

## 操作

個人設定の plan は宣言された設定を GitHub と比較します。apply は plan と所有リポジトリ全体への
影響を示してから確認します。名前で照合して定義を作成・更新し、省略された定義や既存の属性、
選択肢を保持します。既存フィールドの型が異なる場合や、差分判定に必要な情報が揃わない場合は
適用を止めます。選択型を更新するときは既存フィールドを再取得し、選択肢の既存 ID と未宣言の
選択肢を置換リクエストに含めます。途中で失敗した場合は apply を再実行できます。
ドリフト判定の終了コードはリポジトリの plan と共通です。

個人設定の import は認証中のアカウントから設定を読み取り、v2 を出力します。既存ファイルの
更新ではアカウントを照合し、宣言済みの一覧を更新します。GitHub に存在しない宣言と YAML の
コメントは保持します。import には個人の Issue Types と Issue Fields の読み取り権限、apply には
対象定義の書き込み権限が必要です。クラシックトークンと OAuth のスコープは読み取りが
`read:user`、書き込みが `user` です。リポジトリのワークフロートークンには個人アカウントの
設定を変更する権限がありません。
