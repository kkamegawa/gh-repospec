# ADR: importの管理範囲とソース保持refresh

日付: 2026-09-05
追跡: [Issue #11](https://github.com/kkamegawa/gh-repospec/issues/11)

## 決定

`import`は読み取り専用のままにします。スキーマで表現できるリポジトリ状態だけを出力し、取り込めない状態は報告します。`--into`は利用者が既に宣言したフィールドとトップレベルセクションだけを更新します。宣言済みcollectionは完全な管理境界とし、取り込み可能な属性の追加・更新・削除を反映します。seed source、承認済みcommand、secretのsource mapping、optionalフラグ、agentのファイルパスなどローカルの意図は保持します。

YAML refreshはparserでノードを特定しますが、元のbyte範囲を直接編集します。これにより、変更範囲外のコメント、キー順、字下げ、引用符、改行コードを保持します。この保証のためにYAML文書全体を再エンコードしません。JSON入力はJSONとして再整形します。

## 理由

既存リポジトリを管理下へ取り込む際、利用者が宣言していないセクションまで管理対象を黙って広げないことが必要です。collectionを宣言した場合は、古い宣言を削除し、リモートの全collectionを表現するため、collection単位のrefreshが必要です。ローカル設定はGitHubから推測できないため、refresh後も保持します。ソースを最小範囲だけ編集することで、小さなrefreshが無関係な書式差分になることを避けます。

## 結果

- import出力は取り込めない値を省略し、補い方を説明できます。
- 宣言済みcollectionでは`--into`で設定項目を削除できます。これは確認前に表示する意図的な管理境界操作です。
- 実装にはsource-span編集、新規項目の決定的な並び、ラウンドトリップ比較に必要な追加read APIが必要です。
